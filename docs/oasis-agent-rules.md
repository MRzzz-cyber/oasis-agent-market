# Oasis Agent 与 Harness 规则分配

状态：设计方案，供后续实现。当前 PR 的预测市场仍为公共研究能力，不具备完整的预测交易执行 Harness。

## 先实现三个模型角色

这些是职责边界，不要求三个模型同时运行。简单任务只调用主控，需要证据时调用研究，需要跨平台比较时才调用比价角色。先通过明确输入输出和工具白名单建立边界。

| 角色 | 输入与输出 | 可以调用的能力 | 角色规则 |
| --- | --- | --- | --- |
| 主控 Agent | 用户消息、当前 Intent、简化任务状态 → 意图草案或下一步建议 | 创建/修改意图草案、读取任务、请求研究、请求比较、请求订单预览 | 每次最多追问一个必要信息；延续当前盘口上下文；没有用户新确认不增加预算；无证据不报成交；不能自行选择新的签名钱包、收款地址或授予权限 |
| 市场研究 Agent | 主题、事件筛选条件 → 有证据引用的候选盘口 | 搜索市场、读取规则和公开数据；没有钱包或交易工具 | 说明匹配理由、时间与来源；区分市场价格和个人预测；不得编造盘口、胜率或收益；数据失败就标未知；候选推荐不能直接形成交易授权 |
| 事件比较 Agent | 用户选定的候选结果、可信盘口和规则证据 → 可比性说明与比较报告 | 请求规则核验、读取报价与费用、调用确定性深度/成本计算器；没有签名或下单工具 | 核对事件、结果定义、截止时区、结算来源、取消/无效处理；只提出等价候选，不能自己生成“已核验”等价凭证；费用未知不排总成本第一；深度不足不能按顶档价算整单 |

模型角色不直接持有平台交易密钥，不接收浏览器钱包 provider。用户身份由程序注入，不能由模型传入的 userId 或 wallet 字段覆盖。

## 四项能力由程序承担

### Policy Gate：硬规则与约束校验

输入是 Intent、平台能力、可信数据和版本化订单草案，输出是允许、等待条件或明确的阻塞原因。它不依赖“风控模型说通过”。

至少校验：

- 用户、已有钱包、账户、链、资产、市场结果 ID 与当前任务一致。
- 支出、费用上限和累计预算在用户确认范围内；所有金额使用整数最小单位。
- 报价与规则未过期，盘口未关闭，数据来源和资产协议已识别。
- 只有通过可信事件映射/人工维护配置的等价结果才能参加最低总成本排名。
- 平台具备所需能力且用户有资格、账户有正确余额；未知不当作零或已满足。
- 授权是本次所需金额；不允许无限额度、任意合约/地址/模型生成 calldata。
- 当前账户没有未核对的提交；所有花费路径共用跨标签页锁和预算约束。
- 价格、账户、链、收款目标或订单版本变化会使旧确认失效。

### Wallet Executor：钱包确认与提交

只接受已经通过 Policy Gate 且与用户审阅版本绑定的执行请求。使用受控平台适配器构建交易或类型化签名内容，再调用现有钱包。模型不能提供任意 RPC 方法或签名数据。

每一次钱包动作都有清楚含义：切换网络、精确授权、订单签名、实际发送。首次可能有多个钱包确认；界面应合并进度，不能承诺所有平台都只有一个弹窗。充值、跨链、购买、赎回和提款分别审阅，不能隐式串联。

### Receipt Reconciler：结果核验与恢复

提交前保存 pending intent，取得订单号/哈希后立即补记。提交超时先查原订单，不自动重试。核对账户、市场结果、支出、份额、交易日志和平台返回状态。分别报告部分成交、全部成交、取消、失败和无法确认。

“余额变了”“模型认为成功”“页面关闭了”不能解除未决锁。一个错误只进入一处任务状态卡，不重复弹窗；删除视觉警告也不能删除待核对状态。

### Context & Memory：上下文与记忆服务

按账号隔离意图、偏好、历史和交易证据。余额、授权和当前网络每次使用前重新读取；历史记录不能充当实时状态。明确区分事实、用户偏好、模型推测和外部原始文本。

只保留完成任务需要的字段。外部市场描述作为数据，不作为系统指令；签名、私钥、API Secret 和可重放凭证不进入模型上下文或持久日志。新旧域名的浏览器历史迁移另行提供导出/导入，不能当作已经自动同步。

## 规则放在哪一层

| 层次 | 应放的规则 | 执行方式 |
| --- | --- | --- |
| 全局政策 | 用户钱包与身份不变、不得伪造成交、不可自动花费、未知提交必须恢复 | 服务端/浏览器确定性校验；提示词只作解释 |
| Agent 角色 | 职责、可用工具、证据要求、如何说明未知、何时返回主控 | 独立角色提示词 + Harness 工具白名单 |
| 用户 Intent | 本次预算、资产、事件结果、费用与滑点边界、到期条件 | 结构化且版本化存储；修改影响确认状态 |
| 平台适配器 | 网络、抵押资产、协议、签名域、订单字段、最小订单、支持的账户类型 | 受控配置 + 身份/协议/回执验证 + 夹具测试 |
| 工具边界 | 参数 schema、真实用户身份、超时、调用额度、是否只读、重试策略 | 每次工具调用前后统一执行 |

仓库根 AGENTS.md 是开发规范；运行时 Agent 提示词与生产硬规则应独立维护，不能依赖开发规范文件在用户交易时自动生效。

建议的运行时文件边界（尚未创建）：`harness/intent`、`harness/capabilities`、`harness/policy`、`harness/runner`、`harness/events`；角色提示词位于 `harness/prompts`；Polymarket、Kalshi、Arbitrum 适配器各自独立。先复用当前 Worker 与浏览器钱包桥，不先拆微服务。

## 一笔预测订单如何流转

1. 主控形成 Intent 草案；研究角色返回少量候选与证据。
2. 用户选结果，比价角色解释可比性，计算器返回真实深度与成本。
3. Policy Gate 判断是否可预览；不满足时返回一个结构化阻塞原因。
4. 余额不足 → 充值卡；网络不符 → 切换网络入口；平台授权不足 → 账户接入说明。仍保持同一个 Intent。
5. 条件恢复后重新报价，生成用户能读懂的订单预览；不会自动接着下单。
6. 用户确认绑定 reviewDigest、Intent revision、账户和有效期；钱包执行器再申请相应签名。
7. 结果交给回执恢复器；主控只解释已核验的状态。

## 约束 Agent 自身的资源消耗

先给每个 Intent 配置可调整的最大工具步数、模型 Token 预算和执行时限。研究可对公共只读错误作有限重试；所有可能产生资金动作的提交都不自动重试。超出预算或时限时，保存进度并给用户一个可继续的任务状态。

测试应注入恶意盘口描述、错误链、过期价格、模型虚构胜率、预算扩大建议、重复回调、未知提交和刷新恢复。验收以真实任务完成与正确恢复为主，而不是 Agent 数量、推理字数或工具调用次数。
