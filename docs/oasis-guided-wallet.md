# Oasis 引导式对话与账号钱包

## 用户体验与本次范围

回答后的下一步选项是对话主入口，自由输入始终保留。研究 → 确认计划 → 准备资金 → 订单预览 → 单独确认提交 → 交易所回执。完整长期策略表单为可选。

已实现：基于用户明确意图的下一步选项；ETH 测试预算 20 / 50 / 100 USDC；可自由调整；预算传递到订单预览；余额未知、读取失败、余额不足、资金就绪的资金卡片。不会把 AI 文本里的余额或指令当成真实账户状态。其他币种只提供研究选项，不能悄悄换成 ETH 下单。账户切换后清除已验证余额；一分钟前的余额需重新核对。

本次未实现：注册自动开户、主网入金、多链充值、托管、跨链、提现、自动交易。当前连接现有钱包，使用 Hyperliquid Testnet Spot 测试 USDC；复制 EVM 地址不等于完成交易所入金。不能宣称“任意币、任意链都能充”。

## 嵌入式钱包决策

建议评估 Privy 用户控制的嵌入式 EVM 钱包。复用现有 Google 账户，通过官方 custom authentication 集成；不在 Oasis 数据库保存明文私钥，不自研 MPC。具体密钥管理架构、恢复和导出能力应按选定供应商当前方案验收，不能把所有嵌入式钱包统称 MPC。

用户登录只建立账户身份；钱包创建必须稳定映射同一个不可变 user ID，重复登录/重试不得生成新地址。第一阶段不默认添加 Oasis/Agent 为签名者。默认每单用户确认。未来自动化需明确金额、市场、有效期和撤销入口；Hyperliquid API agent 的协议权限与 Oasis 前端额度不是同一个约束。

### 所需外部配置（尚未具备）

1. 创建并配置钱包服务商应用，指定生产/测试环境、允许的域名及 OAuth / custom-auth 配置。
2. 配置服务端身份签发与供应商信任关系；验证 issuer、audience、subject、过期时间与重放边界。任何服务端密钥都只存 Cloudflare Secrets，不发送聊天或前端。
3. 集成官方 SDK 的建钱包/恢复/签名流程；后端独立验证钱包所有权，不能信任前端提交的任意地址。按用户 ID 幂等建立账户绑定。
4. 接入前不展示可用的“系统已创建钱包”或收款地址。未配置时保留现有外部钱包路径。

### 钱包与交易账户的区别

钱包是身份、收款与签名工具，Hyperliquid 交易余额是交易所账本状态。后续主网版本必须明确支持的桥接网络、资产、最小入金与费用；到账检测以目标交易账户的实际余额为准。链上转账成功不能直接显示“交易资金已到账”。

## 注册与入金状态

注册成功 → 建钱包中 → 钱包就绪 / 创建失败可重试 → 选择支持的网络与资产 → 复制地址或供应商入金 → 检测交易账户到账 → 回到原对话预览订单。用户也能只研究或先模拟，研究问题无需入金。

故障要求：登录取消、创建超时、重复请求、恢复/导出、账户切换、转错网络、到账延迟、余额接口异常、报价过期、签名拒绝、部分成交、提交结果未知分别有明确提示和恢复入口。订单状态未知时先对账，禁止自动重复提交。

## 验收与指标

- 每次成功回答后出现 3–4 个相关选项；点击后发出的完整提示在对话中可见，不能悄悄授权。
- 选择测试金额只创建计划；用户必须再次核对金额、数量、限价和网络后才能提交。
- 非 ETH 研究不生成 ETH 交易；模型说余额为零不触发“余额不足”。
- 新老 Google 用户钱包稳定唯一，服务重试不重复建钱包；跨用户无法读写或签名。
- 供应商未配置不生成假钱包或充值成功状态；测试环境不引导真金充值。
- 跟踪选项点击率、研究到计划完成率、钱包创建成功率、到账耗时、预览到确认率、交易所接受/实际成交率、失败恢复率；不以充值金额作为唯一成功指标。
