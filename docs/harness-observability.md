# Harness 后台观察台

本分支提供后台页面、真实事件采集和指标导出。没有生产部署或历史回填；CI 截图中的数据是明确标记的验收夹具。

## 部署与访问

- 入口：`/admin`，页面读取同源 `/api/admin/metrics`。
- 复用现有 Google 登录和账号激活状态。在 Cloudflare 对应环境设置 `OASIS_ADMIN_EMAILS`，值为允许查看后台的已验证 Google 邮箱，多个邮箱使用逗号分隔。没有白名单时不自动授予任何账号管理员权限。
- wrangler.jsonc 增加 `HARNESS_METRICS` / `HarnessMetricsStore` 绑定及 `v2-harness-metrics` SQLite Durable Object 迁移。现有 ACCOUNTS、Privy App/Client ID、issuer、密钥和钱包身份保持不变。
- 部署需要应用这项绑定/迁移。仅合并静态页面不会启用存储。没有绑定时，采集/后台接口明确返回 503，原交易仍可运行。
- 可选：为外部只读 Prometheus 采集器设置 `OASIS_METRICS_READ_TOKEN` Secret（至少 32 个字符）。它只允许读取 Prometheus 路径，不能读取后台 JSON 或写事件；不要复用钱包、JWT 或交易平台密钥。

管理员页面本身不包含私密数据，指标 API 每次验证管理员权限；未登录、无权限、未配置管理员和未启用存储分别显示清楚的状态。后台只有读取、筛选和导出动作。

## 当前采集范围

服务端：已激活登录用户的模型顾问请求、预测盘口搜索、预测盘口报价。模型 HTTP 200 不自动等于成功：观察归一化后的可见 SSE 是否有文本、完成标记或错误。搜索平台全部失败时记录失败。只保留阶段和固定错误码，不存模型输入/输出。

客户端：Arbitrum 购买按钮进入真实执行路径后的钱包确认请求、提交、待回执、取消、成交报告和待核对恢复。报告是第一方最佳努力采集；日志存储故障、浏览器拦截或断网不会阻止交易。没有持久离线补传，可能漏报。

服务端和客户端分别展示。客户端报告不会被提升为服务端独立核验的链上事实；这套指标不能作为授权、成交证明、资金账本或解除交易锁的依据。

尚未覆盖：从首次自然语言需求开始的整个 Investment Intent、完整充值漏斗、预测市场真实购买、模型 Token 成本、独立服务端链上验证，以及跨请求重试关联。不能用已有数据伪装这些能力已经完成。

## 指标口径

| 指标 | 口径 |
| --- | --- |
| 发起任务 | 所选时间范围、来源和类型内具有 task.started 的唯一任务；客户端钱包任务从点击有效购买按钮起算 |
| 完成率 | 已成功任务 / 已发起任务；分母包含未决和用户取消，展示样本数 |
| P50/P95 耗时 | 同一任务从开始事件到成功事件；只统计成功样本，无样本为 null |
| 未决恢复率 | 进入 recovery.required 后又记录恢复或成功的任务 / 明确进入 recovery.required 的任务；普通失败后的新请求尚未关联成重试 |
| 钱包确认请求 | 去重后的授权/兑换确认请求；不表示用户已经签名 |
| 窗口内首笔成功交易耗时 | 按用户在窗口内第一次购买点击到第一次成功报告计算；不是用户生命周期首次交易，也不是从第一次聊天起算 |
| 重复提交拦截 | 执行路径捕获到重复提交保护的事件；不表示发生了重复成交，禁用按钮上的点击未计入 |
| 实际错误成交次数 | 尚无独立核验数据，保持未知；不得显示零 |

时间窗口支持 1/7/30/90 天。任务按开始事件归属；开始事件缺失或在窗口外时不加入完成率分母，并在采集质量中提示。图表展示有采集事件的北京时间日期。读事件上限 20000 条，达到上限时明确标记统计不完整。客户端时间用于客户端耗时，不能当作独立可信审计时钟。

## 存储、权限与隐私

事件写入同源 `POST /api/harness/events`，要求已激活会话、正确 Origin、严格字段白名单及 16 KiB 批次限制。后端分配账号归属和 client 来源；客户端不能伪装成 server。内部 SQL 使用绑定参数，按账号、来源和事件 ID 去重。

只接收随机任务/Trace/Span 标识、固定任务类型、阶段、时间及固定错误码。对话正文、钱包地址、签名、平台凭证和密钥字段会被拒绝。内部账号归属使用 Google subject 的单向摘要，属于假名化标识，后台摘要和导出不返回它。

每个客户端账号每分钟最多接收 240 条事件。存储按事件时间保留 90 天，在写入时清理；这不是无限期审计存档。最近任务最多展示 40 条，页面每条时间线最多展示 80 个事件。

## 兼容方案

| 能力 | 当前支持 | 使用方式与边界 |
| --- | --- | --- |
| Oasis 原生后台 | 已实现 | Worker + SQLite Durable Objects + 原生 HTML/JS；无需新分析平台账号 |
| JSON 指标导出 | 已实现 | 后台下载或读取受管理员会话保护的 API |
| Prometheus / Grafana 指标采集 | Prometheus 文本出口已实现 | `/api/admin/metrics/prometheus?days=7&source=server&type=all`，机器可用专用只读 Bearer Token；第三方采集器尚未配置 |
| OpenTelemetry 日志 | OTLP JSON 日志导出已实现 | 指标 API 增加 `format=otlp`；保留 Trace/Span ID，不包含账号归属；最多导出 1000 条日志 |
| Langfuse 等模型追踪平台 | 尚未接入 | 后续按需要补充真正的 Span、模型 usage 与评测；当前日志导出不等于已经接通模型追踪 |

Prometheus 中滚动窗口计数是 gauge，不伪装成生命周期累计 counter。没有样本的比率和耗时不输出数值。OTLP 当前是手动导出日志 JSON，没有自动向外部平台推送，也没有完整跨 Agent 父子 Span。

## 验证

SQLite 存储测试、权限/来源隔离、事件去重、敏感字段拒收、SSE 错误判定、最佳努力采集与恢复回归测试均使用夹具，不签名、不转账。真实 Chrome 验收覆盖桌面、手机、空数据和无权限状态。另验证现有钱包/预测卡片与 Worker 构建，防止新增采集破坏交易流程。
